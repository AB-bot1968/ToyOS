# ToyOS v67.11-B FIX60U — единая тестовая инфраструктура

FIX60U основан строго на принятом стабильном FIX60T. Рабочие механизмы scheduler, EXECMT, SONARDRV, SONARLOG, SONARVWR, UART/Modbus/Data Channel, supervisor, recovery и syscall ABI функционально не изменяются.

## Что изменено

Все runtime-файлы `.TST` перенесены из корня FAT16 в один плоский каталог `/TST`. Вложенные каталоги внутри `/TST` запрещены. Полный приёмочный набор релиза хранится в `/TST/ACCEPT.TXT`; manifest перечисляет каждый поставляемый `.TST` ровно один раз.

Команда `test` без параметров читает `/TST/ACCEPT.TXT` и последовательно выполняет весь набор. Команда `test NAME.TST` запускает один тест из `/TST`. Перед каждым вызовом `test` файл `/TST/TST.LOG` удаляется/создаётся заново. Итоговые PASS/FAIL-счётчики и acceptance result записываются в него; консоль сохраняет progress и необходимые диагностические сообщения, чтобы зависший тест можно было локализовать.

`LEAKFD.EXE` и `RCONCE.EXE`, ранее открывавшие `TESTCORE.TST` из корня, переведены на абсолютный `/TST/TESTCORE.TST`. Добавлен `TESTTST.TST`, проверяющий доступность manifest, теста из `/TST` и runtime-журнала.

`check_fix60u_test_layout.sh` автоматически запрещает root `.TST`, вложенные каталоги `/TST`, некорректные/дублированные записи manifest, неполный manifest, поставку готового `TST.LOG` и legacy root-ссылки на `.TST` в C-коде. Сохранён FAT 8.3 gate; единственное согласованное исключение — `AUTOSTART.SH`.

`TOYOS_ARCHITECTURE_VISION.md` переведён на русский язык и дополнен FIX60T/FIX60U. В дальнейшем архитектурные изменения документируются там на русском; английские технические термины допустимы.

## Проверка в ToyOS/QEMU

После сборки выполнить:

```text
test
cat /TST/TST.LOG
```

Ожидается финальная строка журнала `ACCEPTANCE: PASSED` и отсутствие `FAILED`/ненулевого `ASSERT FAIL`. Для одиночной проверки допускается, например:

```text
test TESTTST.TST
cat /TST/TST.LOG
```

Каждый новый вызов `test` должен начать новый `TST.LOG`, а не дописывать старый.

### Исправление сборки FIX60U
Устранена остановка `build.sh` непосредственно после `MT25.EXE`: причиной было прежнее ограничение `mkfat16` одним кластером на подкаталог. Плоский `/TST` теперь корректно размещается в многокластерной FAT16 directory chain. Runtime ABI и рабочие механизмы ToyOS не изменены.

## Исправление TST.LOG после QEMU-приёмки
Исправлен `fat_dir_find_free()` для многокластерных подкаталогов: перед расширением FAT-chain теперь просматриваются все уже существующие кластеры. Ранее новый файл мог быть записан после более раннего свободного directory entry (`0x00`) и становился невидимым для lookup. `TESTTST.TST` дополнен `TST_DIR_RW`, который создаёт, повторно открывает, читает и удаляет файл непосредственно в `/TST`.

### Исправление TST.LOG после TESTSUP.TST
Исправлен logger команды `test`: один временный отказ `OPEN` из-за занятых глобальных FAT handles больше не выключает запись журнала до конца приёмки. Открытие `/TST/TST.LOG` выполняется с ограниченным retry и `SYS_RT_YIELD`; окончательный отказ фиксируется как ошибка журнала и делает общий результат `test` FAILED. Добавлена runtime-проверка `TST_APPEND_RW`: файл в многокластерном `/TST` создаётся, закрывается, повторно открывается с APPEND, дописывается и проверяется на точный размер/содержимое `AAAABBBB`.

## Исправление TST.LOG после TESTSUP.TST
- Устранена запись TST.LOG после каждой ASSERT-строки во время выполнения .TST.
- Результаты одного .TST накапливаются в статическом RAM-буфере 4096 байт и одним блоком дописываются после завершения теста и закрытия его входного файла.
- Это исключает влияние test-runner FAT I/O на supervisor/IPC/resource тесты, в частности TESTSUP.TST.
- Переполнение RAM-буфера или ошибка итогового flush являются ошибкой acceptance и явно выводятся на консоль.
- Сохранены runtime-регрессии TST_DIR_RW и TST_APPEND_RW для многокластерного /TST и повторного APPEND.
