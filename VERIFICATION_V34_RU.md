# v34 — эксперимент сохранения контекста на IRQ0

## Цель

v34 делает первый настоящий шаг к вытесняющей многозадачности: при IRQ0 от PIT 50 Hz ядро сохраняет текущий Ring-3 контекст и подставляет контекст второй тестовой задачи.

Это **эксперимент без смены адресного пространства**. Оба процесса A и B используют один и тот же page directory и одну и ту же таблицу страниц. Для различения стеков выделены две дополнительные пользовательские страницы.

## Что добавлено

- `SYS_MT_START = 18` — запуск эксперимента A/B из shell.
- `SYS_MT_STOP = 19` — остановка эксперимента и возврат к shell.
- два kernel-side контекста по 19 слов:
  - 17 слов исходного `struct frame`;
  - `ESP` и `SS`, которые CPU добавляет к frame при переходе CPL3 → CPL0.
- обработка IRQ0 вызывает переключение только если прерван CPL3 (`CS & 3 != 0`).
- при каждом переключении:
  1. текущие 19 слов копируются в контекст A или B;
  2. выбирается другая задача;
  3. её 19 слов копируются обратно в interrupt frame;
  4. обычный `popal`/сегментные `pop`/`iret` продолжают выполнение уже другой задачи.
- A и B имеют отдельные стеки:
  - A: `0x003fd000..0x003fdfff`;
  - B: `0x003fc000..0x003fcfff`.
- shell сохраняется отдельно, поэтому после `SYS_MT_STOP` выполнение возвращается в shell.

## Что намеренно НЕ сделано

- нет CR3 switch;
- нет отдельных page directory;
- нет копирования или клонирования адресного пространства;
- нет sleep/wakeup;
- нет общего планировщика очереди процессов;
- `execq`/`SYS_EXEC_QUEUE=15`/`SYS_QUEUE_STOP=16` не переделывались;
- EXE1 loader не превращён в preemptive scheduler.

## Тест

В Ring-3 shell:

```text
mt-test
```

Ожидается чередование сообщений вида:

```text
=== v34 IRQ0 CONTEXT TEST ===
Two Ring-3 tasks, one address space, separate stacks.
Starting A/B; switch source = IRQ0 at 50 Hz.
[MT-A] start
[MT-B] start
[MT-A] tick ...
[MT-B] tick ...
...
[MT-A] stopping A/B
```

После остановки должен появиться обычный prompt shell.

## Важная граница проверки

Статические проверки и локальная 32-битная компиляция выполняются в доступной среде. Полный PE/COFF build W64DevKit и реальный запуск QEMU в этой среде не считаются выполненными, если они фактически не запускались.
