# Windows 7 x86/x64 — межмашинный тест TAP/QEMU для Toy OS v66.2

## Зачем нужен Bridge

`tap0` создаётся отдельно на каждом физическом ПК. Сам по себе TAP не соединяет два разных Windows-хоста. Для передачи Ethernet/ARP между ПК нужно объединить на каждом ПК физический LAN-адаптер и `tap0` в Windows Network Bridge. OpenVPN описывает именно такую схему: выбрать LAN-интерфейс и TAP-интерфейс и выбрать Bridge; IP-настройки после этого относятся к интерфейсу моста. См. официальную документацию OpenVPN по Windows bridging.

## ПК №1 — Master

1. Открой `Win+R` -> `ncpa.cpl`.
2. Выдели физический Ethernet-адаптер, через который ПК подключён к локальной сети, и `tap0` (Ctrl+клик).
3. Правой кнопкой -> `Мостить подключения`.
4. Появится `Сетевой мост`.
5. Для первого теста адрес Windows-хоста можно оставить как был; IP Toy OS будет отдельным: `192.168.100.10/24`.
6. Запусти QEMU с `ifname=tap0`.

## ПК №2 — Slave

Повтори те же действия: физический LAN-адаптер + `tap0` -> `Мостить подключения`.

Toy OS получает `192.168.100.11/24` для SLAVE1.

## Важно

Не задавай одинаковый IP Windows-хостам и гостевым Toy OS. Для проверки Toy OS достаточно, чтобы два гостя находились в одной L2-сети. Для этой первой схемы шлюз не нужен: Master и Slave находятся в одной подсети `/24`.

## Проверка ARP до запуска телеметрии

Сначала запусти Master:

`exec NETDRV.EXE TELEMETRY MASTER 5000`

Затем Slave1:

`exec NETDRV.EXE TELEMETRY SLAVE1 192.168.100.10`

На Slave1 ожидается:

`NETDRV: UDP SLAVE running independently`

затем при появлении кадра ARP:

`NETDRV: ARP OK`

## Если снова ARP failed

В текущей версии Slave не завершается — он продолжает работать и повторяет ARP. Если `ARP OK` так и не появляется, проблема находится ниже IP/UDP: проверяй, что `tap0` и физический адаптер действительно входят в `Сетевой мост`, что оба ПК физически соединены одной LAN, и что мост активен. На Windows 7 известны случаи, когда созданный TAP/LAN bridge после sleep/hibernate перестаёт передавать кадры; OpenVPN рекомендует учитывать состояние самого bridge. Перезагрузка/перезапуск bridge является диагностическим тестом.

## Тест без третьего ПК

Третий компьютер не нужен для проверки независимости ролей.

На ПК №1 оставь Master.

На ПК №2 сначала запусти SLAVE1 и убедись, что он работает. Затем останови его и запусти вместо него:

`exec NETDRV.EXE TELEMETRY SLAVE2 192.168.100.10`

SLAVE2 использует `192.168.100.12` и должен самостоятельно выполнить ARP Master и начать передачу. Работа SLAVE2 не зависит от SLAVE1.

Для одновременного запуска SLAVE1 и SLAVE2 на одном физическом ПК потребуется второй TAP-интерфейс, например `tap1`, с отдельным QEMU-сеансом; это не требуется для текущего функционального теста.
