# VERIFICATION V46 — исправление мусора и зависаний при `exec` / `execq`

## Причина

В v45 `SYS_CONSOLE_WRITE` выполнял посимвольную запись с разрешёнными аппаратными прерываниями. Поэтому PIT мог прервать Ring-3 задачу прямо внутри одной логической записи консоли. Для `execmt` это позволяло планировщику вставить диагностическую строку между символами `Task NN`.

Кроме того, переходы из EXE/планировщика обратно в shell выполнялись без отдельной критической секции.

## Исправление v46

1. Добавлен `console_write_atomic_n()`.
2. `SYS_CONSOLE_WRITE` теперь выполняет всю переданную пользователем строку как одну неперемежаемую операцию относительно PIT:
   - сохраняется исходный IF;
   - выполняется `CLI`;
   - выводится вся строка;
   - исходное состояние IF восстанавливается.
3. Переходы `exe_exit()`, `sched_dispatch_next()` и `sched_stop()` защищены `CLI` до момента возврата через `IRET`. Итоговый IF берётся из восстанавливаемого interrupt frame.
4. Формат `Task NN\n` из v45 сохранён.
5. Диагностическая строка планировщика сохранена.
6. `ls`, меню, команды shell, `exec`, `execq`, `execmt` и остальные возможности не удалялись и не менялись по назначению.

## Ожидаемое поведение

`exec MT01.EXE`:

```text
Task 01
Toy0>
```

без трёх посторонних символов.

`execq 2 MT01.EXE`:

```text
Task 01
Task 01
execq: finished
Toy0>
```

без посторонних символов и без зависания.

Для `execmt` диагностическая строка `[MTxx] RUNNING ...` остаётся выше пользовательской строки `Task NN`.

## Проверка исходников

`check46.sh` проверяет наличие атомарного пути `SYS_CONSOLE_WRITE` и защиты переходов контекста.

Linux-host дополнительно подтвердил синтаксическую корректность `src/kernel.c` с `gcc -m32 -fsyntax-only`.

Полная штатная сборка W64DevKit/Windows 7/QEMU в текущем Linux-окружении не выполняется, поскольку проект требует i686 W64DevKit.
