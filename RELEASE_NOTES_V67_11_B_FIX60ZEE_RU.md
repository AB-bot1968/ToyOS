# ToyOS v67.11-B FIX60ZEE

## Причина релиза

На FIX60ZED четыре RT-задачи с параметрами 10/10 мс уже выполнялись равномерно, но RTSTAT показывал одинаковое накопление MISS/SKIP, а после `exec SONARVWR.EXE` консоль могла зависнуть при продолжающейся работе фоновых сервисов. Дополнительно `TESTMRT.TST` ложно требовал ровно 8 записей в активно растущем SONAR.LOG.

## Исправления

- Убрана активная роль `rt_shell_hold`: MT получает post-RT slack непосредственно после полного RT-sweep, без пропуска следующего 10-мс RT release.
- `SYS_PROCESS_WAIT` чередует RT и MT service opportunities и не может бесконечно держать ожидаемый MT-процесс в READY при 4x10-мс RT.
- Удалено скрытое преобразование `exec SONARVWR.EXE` в MT spawn+wait.
- Live-viewer запускается явно командой `execmt SONARVWR.EXE`.
- Если MT-сессия уже активна, одиночный `execmt` добавляет процесс через PROCESS_SPAWN и печатает PID. Несколько файлов по-прежнему означают создание новой MT-сессии.
- В тестовом DSL добавлен `SONAR_LOG_MIN N` для живого циклического журнала; точный `SONAR_LOG_VALID 128` сохранён.
- `TESTVWR.TST` усилен сценарием 2 MT + 4 RT (10/10 мс) и многократным `execmt SONARVWR.EXE` с `WAIT LAST`.

## Команды live-просмотра

При работающих `SONARPUB.EXE SONARLOG.EXE` использовать:

`execmt SONARVWR.EXE`

Shell вернёт PID добавленного MT-процесса. Для синхронного ожидания при необходимости используется `wait PID`.

`exec SONARVWR.EXE` больше не маскируется под MT и выводит подсказку использовать `execmt` для live-view.
