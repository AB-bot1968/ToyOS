# v39 — EXECMT, 25 независимых EXE1-задач

## Цель

v39 расширяет scheduler v38 до запуска до **25 реальных EXE1** одновременно в одной scheduler-сессии. Старые `exec`, `execq`/`execq forever` и syscalls 20–22 сохраняются.

## Архитектура

- `EXECMT_MAX_TASKS = 25` и `SCHED_TASKS = 25`.
- Каждая задача получает собственный CR3 и собственную структуру контекста.
- Все задачи используют тот же виртуальный адрес EXE1 `0x00100000`, но получают отдельный физический image slot размером 1 MiB.
- Стек остаётся на общем виртуальном адресе `0x003fd000`; физическая страница стека различается для каждой задачи.
- Состояния scheduler: `CREATE -> READY -> RUNNING -> BLOCKED/STOPPED -> EXIT`.
- IRQ0 50 Hz выполняет round-robin переключение среди READY задач.
- `SYS_EXECMT = 23`: EBX = packed names, ECX = count (1..25).
- Перед загрузкой проверяется доступная RAM: для N задач требуется физический диапазон от `0x00400000` до `0x00400000 + N*0x00100000`.

## EXE1

`execmt` использует тот же формат EXE1 и FAT16, что и обычный `exec`. Для каждой задачи kernel:

1. проверяет размер файла и EXE1 header;
2. выбирает отдельный физический 1-MiB slot;
3. переключается на CR3 задачи;
4. читает image из FAT16 в виртуальный `0x00100000`;
5. обнуляет BSS;
6. помечает фактический image диапазон `US=1`;
7. создаёт 19-word CPL3 context;
8. переводит задачу в READY.

## Тестовые EXE

`src/execmt_task.c` компилируется 25 раз с `-DEXECMT_ID=1..25` и создаёт:

`MT01.EXE ... MT25.EXE`

Задача 2 блокируется, задача 3 будит задачу 2, после чего все задачи завершаются через `SYS_SCHED_EXIT`.

Пример:

```text
execmt MT01.EXE MT02.EXE MT03.EXE MT04.EXE MT05.EXE MT06.EXE MT07.EXE MT08.EXE MT09.EXE MT10.EXE MT11.EXE MT12.EXE MT13.EXE MT14.EXE MT15.EXE MT16.EXE MT17.EXE MT18.EXE MT19.EXE MT20.EXE MT21.EXE MT22.EXE MT23.EXE MT24.EXE MT25.EXE
```

## Размер kernel.bin

Bootloader по-прежнему читает фиксированный слот **64 сектора = 32768 байт**. `build.sh` пересчитывает `KERNEL_BYTES` и `KERNEL_SECTORS` после линковки и завершает сборку с ошибкой, если kernel превышает 64 сектора. Увеличение числа scheduler page directories/tables находится в BSS и не должно маскироваться как рост raw kernel; фактический raw размер всё равно проверяется.

## Ограничение проверки

Полная сборка W64DevKit и запуск QEMU на Windows 7 в текущем окружении не выполнялись. Поэтому этот документ описывает исходный код и автоматические статические проверки, а не заявляет неподтверждённый runtime PASS.
