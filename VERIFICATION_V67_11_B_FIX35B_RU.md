# Проверка ToyOS v67.11-B FIX35B

## 0. Контрольная точка
FIX34A остается стабильной точкой отката. FIX35B фиксировать как stable только после runtime-проверки ниже.

## 1. Главный регрессионный тест — обязательно первым
1. Подготовить несколько SENSOR RT-задач обычным способом.
2. Добавить FAULTPF.EXE с параметрами RT так, чтобы его priority был ВЫШЕ хотя бы одной SENSOR-задачи (точно повторить конфигурацию, зависавшую в FIX35/FIX35A).
3. Нажать F10.
4. После fault должен остаться рабочий `toy0>`; не должно быть fatal `EXC 14 ...` и не должно быть состояния, когда курсор мигает, но ввод не работает.
5. Сразу выполнить последовательно: `ps`, `rtstat`, `rtdata SLOTn` для живого SENSOR, затем простую команду `ls`.
6. Через 10–20 секунд повторить `rtstat`: jobs живых SENSOR должны продолжать изменяться.
7. `ps <PID fault-задачи>` должен показать EXITED/FAULT, VECTOR=14; для штатного FAULTPF ожидаемый CR2 1342177280 (0x50000000).

## 2. Три положения priority
Повторить FAULTPF отдельно:
- priority ниже всех SENSOR;
- priority между SENSOR;
- priority выше всех SENSOR.
Во всех случаях fault завершается локально, shell остается интерактивным, остальные RT продолжают работать.

## 3. Другие exception
Повторить тест раздела 2 для FAULTUD.EXE (#UD, vector 6) и FAULTGP.EXE (#GP, vector 13). Проверить `ps PID`.

## 4. RT + MT
1. Запустить 4 MT, проверить рост `mtstat`.
2. Запустить несколько SENSOR и fault RT с priority выше части SENSOR.
3. После fault выполнить `ps`, `rtstat`, `mtstat`, `rtdata`, `mtdata`.
4. Подождать 20–30 секунд и убедиться, что RT и MT статистика живых задач продолжает расти.
5. `mtstop all` должен срабатывать с первого Enter.

## 5. syscall-test
Исправление FIX35A сохранено. Запустить syscall-test без фоновых задач, затем с RT, затем с RT+MT. На запросе `type OK then Enter` тест обязан реально ждать ввода. Ввести `OK` и Enter; тест должен пройти.

## 6. Регрессии стабильной линии
Проверить: 8 SENSOR; RTSTAT WATCH + ESC; MTSTAT WATCH + ESC; PROCID как FG/MT/RT; RTDATA/MTDATA; остановку RT по SLOT; `VGADRV.EXE SPLASH.RAW` при активных MT/RT; обычные ls/mkdir/файловые операции.

## Критерий успеха
FIX35B можно фиксировать только если fault RT с более высоким priority, чем у работающего SENSOR, больше не повреждает интерактивный shell и не останавливает остальные RT/MT задачи.
