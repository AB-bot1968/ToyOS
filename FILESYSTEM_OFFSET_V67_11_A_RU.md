# ToyOS v67.11-A — перенос начала FAT16 на LBA 512

## Цель

v67.11-A изменяет только физическую раскладку дискового образа перед следующим RT-этапом.
Начало FAT16 переносится с LBA 130 на **LBA 512**.

## Новая раскладка

- LBA 0 — BIOS boot sector;
- LBA 1..128 — фиксированный kernel slot, 128 секторов / 64 KiB;
- LBA 129..511 — резервная область, 383 сектора / 196096 байт;
- LBA 512 — FAT16 boot sector (BPB);
- далее — FAT16 FAT/root/data области.

Размер образа сохраняется 8192 сектора = 4 MiB. Поэтому после переноса начало
FAT16 объём тома в BPB составляет 8192 - 512 = 7680 секторов.

## Почему выбрано 512

512 секторов дают ровную границу 256 KiB перед файловой системой и оставляют
достаточный запас для будущих системных структур. Уменьшение значения не нужно:
сейчас важнее иметь стабильную и легко проверяемую границу.

## Совместимость

Изменение не меняет:

- загрузку kernel с LBA 1;
- размер kernel slot;
- protected-mode ABI;
- syscall ABI;
- FAT16 BPB-формат;
- FAT16 cluster addressing после чтения BPB.

Kernel по-прежнему вычисляет FAT/root/data LBA относительно прочитанного BPB,
поэтому после изменения `FAT_LBA` файловый слой не содержит жёстко заданных LBA
FAT/root/data.

## Изменённые исходники

- `src/kernel.c` — `FAT_LBA = 512`;
- `tools/mkfat16.c` — `PART_LBA = 512`;
- `tools/fat16check.c` — `FAT_LBA = 512`;
- `build.sh` и regression checks — новая геометрия образа;
- `VERSION.txt` — `Toy OS v67.11-A`.

## Проверки

`check137.sh` проверяет:

1. FAT16 BPB находится ровно на LBA 512;
2. kernel slot остаётся 128 секторов;
3. LBA 129..511 остаётся резервным gap;
4. BPB содержит 7680 total sectors;
5. kernel/mkfat16/fat16check используют одинаковый LBA;
6. FAT16-файлы из root и вложенных каталогов доступны через `fat16check`.

Полная i386-сборка должна выполняться исходным W64DevKit/i686 toolchain.
