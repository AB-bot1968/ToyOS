# Проверка ToyOS v67.11-B FIX34A

## Цель
Подтвердить исправление зависания, обнаруженного в FIX34, и отдельно доказать, что новый unified process identity resolver работает для FG/MT/RT без изменения scheduler policy.

## 1. Обязательный regression-тест обнаруженной ошибки
1. Загрузить чистую FIX34A.
2. Запустить PROCID.EXE как RT-задачу с period=10 ms, deadline=10 ms, priority=1 тем же способом, которым воспроизводилась ошибка FIX34.
3. Дождаться сообщения о старте и приглашения `toy0>`.
4. Не менее 10 секунд вводить команды `ps`, `rtstat`, `rtdata SLOT1` несколько раз.

Ожидается: консоль принимает команды сразу; система не зависает. `ps` показывает PROCID.EXE как RT (обычно BLOCKED между jobs). `rtstat` показывает рост jobs. `rtdata SLOT1` содержит `TYPE:RT` и правильный PID/SLOT.

## 2. Длительная проверка RT 10/10/1
Оставить PROCID.EXE работающим 1–2 минуты. Периодически выполнять `rtstat` и `rtdata SLOT1`. Jobs должны продолжать расти, shell должен оставаться интерактивным. Затем `rtstat stop SLOT1`; `ps` должен показать RT запись EXITED. Повторный запуск в том же SLOT1 обязан получить новый PID.

## 3. FG identity
Выполнить `exec PROCID.EXE` без MT/RT, затем с активными MT, затем с активными RT. Во всех случаях foreground запуск обязан вывести `TYPE:FG`. После завершения `ps` показывает соответствующий FG PID как EXITED.

## 4. MT identity
Запустить PROCID.EXE через EXECMT. По `ps` определить MTn, затем `mtdata MTn`. Данные должны содержать `TYPE:MT`, тот же PID и тот же MTn. `mtstat` должен продолжать увеличивать D/Q/C.

## 5. Совместная нагрузка
Запустить несколько MT и несколько RT, включая PROCID.EXE 10/10/1. Проверить `ps`, `mtstat`, `rtstat`, `mtdata`, `rtdata`, затем обычный `exec PROCID.EXE`. Foreground экземпляр должен определиться как FG; фоновые — как MT/RT. Shell должен оставаться интерактивным.

## 6. Сохранение прежних исправлений
Проверить `rtstat watch` + ESC, `mtstat watch` + ESC, `mtstop all` с первого Enter и `exec VGADRV.EXE SPLASH.RAW` при активных MT/RT. Поведение должно соответствовать FIX32/FIX33.

## Критерий фиксации
FIX34A можно считать стабильной только после runtime/QEMU прохождения пунктов 1–6. FIX33 до этого остаётся контрольной стабильной версией.
