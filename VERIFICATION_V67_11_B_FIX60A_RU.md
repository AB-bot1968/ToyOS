# ToyOS v67.11-B FIX60A — проверка загрузки системных EXE

## Причина
Физический тест FIX60 обнаружил `execmt SONARDRV.EXE -> FAIL 4294967293`. В ядре это `EXE_ERR_OPEN=-3`: ошибка возникает до чтения EXE1 и до исполнения SONARDRV. После появления cwd старое 13-байтовое поле имени EXECMT не позволяет записать `/SONARDRV.EXE`, а простое `SONARDRV.EXE` разрешалось только относительно cwd.

## Исправление
Загрузчик исполняемых файлов сначала сохраняет прежнюю семантику: ищет простое имя относительно cwd. Только если файл не найден и имя не содержит `/` или `\\`, выполняется повторный поиск того же 8.3 имени в ROOT. Обычный FAT16 file I/O не изменён. ABI syscall не изменён. Syscall 13/14 не изменены.

## Новый автоматический тест
`TESTEXE.TST`:
1. приводит MT/RT/SAFE/HWWD к чистому состоянию;
2. переходит в `/DOC`;
3. выполняет реальный `execmt HBEATOK.EXE`;
4. требует `MT_ACTIVE 1`;
5. останавливает MT и требует `MT_ACTIVE 0`;
6. возвращается в `/`;
7. структурно проверяет наличие `/SONARDRV.EXE` через `ASSERT FILE_EXISTS`;
8. проверяет отсутствие MT/RT/handles, NORMAL, HWWD disarmed, HEALTH NORMAL.

Это закрывает пробел TESTSON: прежний тест проверял sonar core, но не факт доступности исполняемого SONARDRV через реальный loader path.

## Проверка на целевой системе
После сборки сначала выполнить:
`test TESTEXE.TST`
Требуется `FAIL=0`.

Затем выполнить весь прежний набор автоматических тестов FIX60. Везде требуется `FAIL=0`.

После этого для физического теста QEMU/com0com/SONARSIM выполнить `execmt SONARDRV.EXE`. Ошибки `FAIL 4294967293` быть не должно.

## Architecture Vision
`TOYOS_ARCHITECTURE_VISION.md` обновлён: зафиксирован ROOT fallback только для простых legacy 8.3 имён исполняемых файлов. FAT16 cwd semantics для обычных файлов и I/O-port architecture не изменены.
