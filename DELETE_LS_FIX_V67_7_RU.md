# ToyOS v67.7 — исправление удаления файлов и последующего `ls`

## Симптом

Для некоторых файлов, в частности `010101.TXT`, команды `delete` и `rm` сообщали об успешном удалении, однако последующий `ls` продолжал показывать имя файла.

## Причина

FAT16 хранит удалённую запись каталога с первым байтом `0xE5`. Предыдущая реализация `fat_delete()` освобождала цепочку кластеров и меняла только первый байт найденной directory entry.

Для корректной обычной FAT16-записи этого достаточно, однако в старых/повторно изменявшихся образах могли существовать дополнительные обычные directory entries с тем же 8.3-именем. В таком случае одна запись становилась `0xE5`, а другая оставалась видимой для `ls`.

Дополнительная проблема диагностики состояла в том, что остальные 31 байт старой записи продолжали содержать имя и метаданные. Хотя `ls` обязан игнорировать `0xE5`, полное обнуление записи делает состояние каталога однозначным и предотвращает использование устаревших полей.

## Изменение 1 — полное удаление directory entry

Добавлена `fat_mark_deleted_entry()`.

После успешного освобождения FAT-цепочки она:

1. перечитывает сектор каталога;
2. обнуляет все 32 байта directory entry;
3. устанавливает первый байт в стандартный FAT16 marker `0xE5`;
4. записывает сектор обратно.

Таким образом, запись одновременно имеет стандартный статус deleted и не содержит старых имени/атрибутов/кластеров/размера.

## Изменение 2 — очистка возможных дубликатов

Добавлена `fat_delete_duplicate_entries()`.

После удаления основной записи родительский каталог повторно просматривается с тем же нормализованным 8.3-именем. Любые дополнительные обычные файловые записи с таким именем также переводятся в состояние deleted и полностью очищаются.

Проверяются оба варианта каталога:

- FAT16 ROOT;
- обычный каталог с кластерной цепочкой.

Директории, LFN entries и volume-label entries при этой очистке не удаляются.

## Изменение 3 — порядок операции

`fat_delete()` теперь:

1. нормализует путь;
2. находит directory entry;
3. проверяет, что объект является обычным файлом;
4. сохраняет начальный кластер;
5. освобождает FAT-цепочку;
6. полностью помечает найденную запись удалённой;
7. очищает возможные старые дубликаты того же имени.

Syscall `SYS_FILE_DELETE` и команды `rm`/`delete` не изменены по интерфейсу.

## Совместимость

Не изменялись:

- syscall ABI;
- формат FAT16;
- размер directory entry (32 байта);
- shell ABI;
- история команд;
- регистронезависимость команд;
- механизм `ls`.

## Проверка

`check133.sh` проверяет наличие нового полного удаления directory entry и очистки дубликатов.

`src/kernel.c` успешно скомпилирован в 32-битном freestanding режиме с проектными ограничениями GCC.
