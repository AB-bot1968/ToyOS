# Проверка FIX33

1. Загрузить систему без RT/MT. Выполнить `ps`. Команда не должна повреждать shell.
2. Запустить 1..25 MT через существующий EXECMT. Выполнить `ps`: у каждой загруженной MT должен быть ненулевой PID, TYPE=MT и MT1..MT25; PID не обязан совпадать с номером MT-слота.
3. Запустить RT SENSOR через F10/RTD. Выполнить `ps`: RT должны иметь отдельные PID, TYPE=RT и SLOT1..SLOT8.
4. Совместно 25 MT + 8 RT: проверить `ps`, затем MTSTAT/MTSTAT WATCH и RTSTAT/RTSTAT WATCH. Статистика и планирование должны вести себя как в FIX32.
5. Выполнить `mtstop MTn`, `mtstop all`, `rtstat stop SLOTn`; повторить `ps`. Остановленные/завершенные записи могут отображаться как EXITED до повторного использования/переинициализации соответствующего слота.
6. Проверить foreground `exec VGADRV.EXE SPLASH.RAW` без фоновых задач, с MT, с RT и совместно: поведение FIX32 должно сохраниться.
7. Проверить, что новые запуски получают новые PID; PID является идентичностью экземпляра, а MTn/SLOTn — местом исполнения.

FIX33 специально НЕ реализует wait, exit status ABI, spawn/argv, Ring3 exception containment, ownership файловых дескрипторов и не переводит scheduler на process table.
