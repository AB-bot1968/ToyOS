# Проверка ToyOS v67.11-B-FIX2

Дата проверки: 2026-09-20.

## 1. Проверка цепочки базовых версий

Проверенное дерево содержит:

`v67.11-A → v67.11-B → v67.11-B-FIX1 → v67.11-B-FIX2`

В исходниках одновременно присутствуют:

- `src/kernel.c`: `FAT_LBA = 512`;
- `tools/mkfat16.c`: `PART_LBA = 512`;
- `tools/fat16check.c`: `FAT_LBA = 512`.

Следовательно, v67.11-A не была только документальным изменением: смещение FAT16 реально присутствует в коде и было унаследовано последующими версиями.

## 2. Независимая проверка FAT16

Host-утилиты `mkfat16.c` и `fat16check.c` собраны с `-Wall -Wextra -Werror`.

Создан тестовый образ и проверен непосредственно сектор `LBA 512`:

- signature: `55 AA`;
- bytes/sector: 512;
- sectors/FAT: 32;
- FAT16 volume sectors: 7680;
- общий тестовый image: 8192 sectors;
- `fat16check` подтвердил `X.EXE`.

Это исключает ситуацию, когда константа 512 есть только в исходнике, но builder фактически пишет FAT16 в старое место.

## 3. Что означают `128/128` в build.sh

Строка:

```text
[KERNEL] kernel.bin: ... (128/128 sectors)
```

относится к **kernel slot**, а не к FAT16.

Архитектура текущего загрузчика:

```text
LBA 0          BIOS boot sector
LBA 1..128     kernel slot = 128 sectors = 64 KiB
LBA 129..511   reserved gap = 383 sectors
LBA 512        FAT16 boot sector
LBA 513...     FAT16 volume
```

Поэтому `128/128` не является ошибкой смещения FAT16. В FIX2 `build.sh` дополнительно печатает явную строку `[FAT16] filesystem start: LBA 512`, чтобы эти два разных размера больше не путались.

## 4. Причина SENSOR1..SENSOR4

В FIX1 идея была правильной: F10 должен передать RTD приватный параметр `q`, чтобы RTD не включал диагностическую печать SENSOR.

Но индексация была ошибочной:

```text
base = EXEC_ARG_SIZE
k = EXEC_ARG_SIZE
base + k = EXEC_ARG_BLOCK_SIZE
```

поэтому поиск конца строки сразу попадал за границу второй половины argument block и `q` не записывался.

FIX2 исправляет это на:

```text
base = EXEC_ARG_SIZE
k = 0
```

Теперь `q` действительно добавляется после числовых аргументов.

RTD при `q`:
- создаёт RT-задачу;
- не включает `diag_verbose`;
- не печатает `RTD: started ...`.

SENSOR1..SENSOR4 получают `verbose=0` и не печатают каждый цикл.

## 5. Что остаётся источником данных

Измерения продолжают собираться ядром независимо от консольного вывода:

- `rtstat` — сводка;
- `rtstat compare` — сравнение;
- `rtstat watch` — живой монитор;
- `rtstat dump` — последние raw samples;
- `rtstat reset` — начало нового окна измерений.

`RTDATA` в этой версии ещё не реализован.

## 6. ABI

Syscall ABI `1..48` не менялся. Syscall 49 для будущего RTDATA здесь не добавляется.

## 7. Компиляция

Успешно выполнена freestanding i386 syntax-only проверка с `-Werror` для:

- `src/kernel.c`;
- `src/user_shell.c`;
- `src/rtd.c`;
- `src/rt_sensor_diag.c`.

Также успешно собраны host-утилиты FAT16 и проведён реальный тестовый образ.

Полная сборка boot/kernel/user и загрузка в QEMU в данном окружении не выполнялись, поскольку отсутствуют требуемые W64DevKit/i686 и QEMU. Поэтому runtime PASS в эмуляторе здесь не заявляется.
