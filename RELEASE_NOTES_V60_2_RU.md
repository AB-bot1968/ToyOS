# Toy OS v60.2 — исправление FAT16 ROOT и состава системного образа

## Исправленная ошибка

В v60/v60.1 построитель FAT16 проверял при добавлении записи в ROOT DIRECTORY
только первые 16 записей (один сектор). При добавлении большого набора системных
файлов это приводило к ошибке после заполнения первого сектора root, хотя FAT16
ROOT рассчитан на 512 записей.

В v60.2 добавлена отдельная функция `put_root_entry()`, которая просматривает все
`ROOT_ENTRIES` записей (32 сектора) и корректно размещает файлы после 16-й записи.

## Дополнительное исправление безопасности

Проверка размещения кластеров теперь учитывает фактический размер создаваемого
образа, а не только теоретический предел FAT16. Это предотвращает выход за границы
буфера при ошибочно большом наборе входных файлов.

## Состав ROOT

В корневой каталог теперь обязательно помещаются:

- `BOOT.BIN` — копия загрузочного сектора;
- `HELLO.EXE`;
- `COMDRV.EXE`;
- `LOADER.EXE`;
- `NETDRV.EXE`;
- `NET.CFG`;
- все Q*.EXE;
- все MT01.EXE ... MT25.EXE.

Каталоги v60 сохраняются:

- `BIN/HELLO.EXE`;
- `BIN/NETDRV.EXE`;
- `DOC/NET.CFG`.

## Проверки

`check62.sh` выполняет три независимых уровня:

1. аудит исходного кода исправления ROOT;
2. синтаксическая и две объектные компиляции `mkfat16.c`;
3. проверку фактически созданного образа через `fat16check`.

Полная нативная сборка kernel/boot под Windows 7 + W64DevKit x86 должна быть
выполнена в соответствующей среде пользователя; здесь она не объявляется
выполненной без наличия этого toolchain.
