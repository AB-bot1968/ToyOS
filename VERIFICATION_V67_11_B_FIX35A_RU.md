# Проверка ToyOS v67.11-B FIX35A

## 0. Перед началом
FIX34A остается подтвержденной точкой отката. FIX35A считать кандидатом до полного прогона. Собрать обычным W64DevKit build.sh и загрузить полученный образ так же, как предыдущие версии.

## 1. Точный регрессионный тест обнаруженной ошибки
1. Подготовить через RTD несколько SENSOR-задач с теми же параметрами, на которых воспроизводился FIX35.
2. Добавить FAULTPF.EXE так, чтобы ее RT priority была НИЖЕ всех SENSOR. Нажать F10. Система должна остаться интерактивной; fault PID должен быть EXITED/FAULT; SENSOR продолжают работу.
3. Повторить после перезапуска, но дать FAULTPF priority ВЫШЕ хотя бы одной SENSOR, то есть точно воспроизвести конфигурацию, которая в FIX35 давала `EXC 14 ...` и зависание.
4. После F10 не должно быть fatal-строки `EXC 14 ...` и зависания. Должен вернуться рабочий `toy0>`.
5. Выполнить `ps`, затем `ps PID` для fault PID. Ожидается TYPE RT, STATE EXITED, EXIT FAULT, VECTOR 14. Для FAULTPF CR2 должен быть 1342177280 (0x50000000).
6. Несколько раз выполнить `rtstat` и `rtdata SLOTn` для оставшихся SENSOR: jobs/data должны продолжать обновляться.

## 2. RT->RT разные позиции приоритета
Повторить FAULTPF минимум в трех положениях: самый низкий priority, между двумя SENSOR, самый высокий priority. В каждом случае fault завершается локально, shell отвечает, остальные RT продолжаются. Затем аналогично кратко проверить FAULTUD и FAULTGP хотя бы в положении выше одной SENSOR.

## 3. RT + MT
1. Запустить 4 MT минимальных задачи и убедиться через `mtstat`, что счетчики растут.
2. Запустить несколько SENSOR и FAULTPF с priority выше хотя бы одной SENSOR.
3. После fault проверить `ps`, `rtstat`, `mtstat`, `rtdata`, `mtdata`.
4. Оставшиеся RT и MT должны продолжать работу; фоновые fault-задачи ничего не печатают в shared console.
5. `mtstop all` должен сработать с первого Enter.

## 4. syscall-test
1. Сначала без RT/MT выполнить `syscall-test`.
2. На строке `[02] SYS_CONSOLE_READ: type OK then Enter:` тест обязан реально ждать клавиатуру. Ввести `OK` и Enter. Пункт 02 должен показать PASS.
3. Повторить `syscall-test` при работающих RT, затем при RT+MT. Внутренние scheduler hand-off не должны проскакивать как ввод: тест продолжает ждать O, K и Enter.
4. Остальные пункты syscall-test должны вести себя как в стабильной базе. Scratch disk test использует LBA 300; FAT16 остается с LBA 512.

## 5. Остальные FIX35 containment тесты
Проверить `exec FAULTUD.EXE`, `exec FAULTGP.EXE`, `exec FAULTPF.EXE`; shell должен возвращаться. Проверить fault-программы как MT и RT. `ps PID` должен сохранять vector/error/EIP/CR2 для завершившегося PID. Повторный запуск в освободившемся слоте получает новый PID.

## 6. Регрессии стабильной линии
- `rtstat watch`, выход ESC;
- `mtstat watch`, выход ESC;
- 8 SENSOR одновременно;
- 25 MT при возможности, либо обычный проверенный набор;
- совместная RT+MT нагрузка;
- `mtstop all` с первого Enter;
- `exec VGADRV.EXE SPLASH.RAW` без RT/MT, с MT и с RT+MT;
- `PROCID.EXE` как FG/MT/RT: identity должна соответствовать FIX34A.

## Критерий принятия
FIX35A можно фиксировать как стабильную только если воспроизводившая FIX35 конфигурация с более приоритетной FAULTPF больше не выводит fatal `EXC 14` и не зависает, syscall-test действительно ждет `OK`, а перечисленные регрессии FIX34A проходят.
