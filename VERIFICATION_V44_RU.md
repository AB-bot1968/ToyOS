# v44 — исправление EXEC/EXECQ и нормального вывода EXECMT

## Исправления

1. `SYS_SCHED_EXIT=22` теперь корректно завершает обычный EXE1, если планировщик EXECMT не активен: используется существующий `exe_exit()`.
   Поэтому `exec MT01.EXE` больше не зависает, а `execq 2 MT01.EXE` корректно переходит к следующему повтору и завершает очередь.
2. Сохраняется прежнее поведение EXECMT: при активном планировщике `SYS_SCHED_EXIT` переводит текущую задачу в `TASK_EXIT` и передаёт управление следующей задаче.
3. Вывод `MTxx.EXE` очищен от старого префикса `[EXECMT-xx]`. Каждая задача печатает отдельную строку вида:
   `Task 01: Ring-3 task is running; private CR3/stack active`
4. Дополнительные строки блокировки/пробуждения Task 02/03 также используют формат `Task NN:`.
5. Диагностическая строка ядра `[MTxx] RUNNING ...` остаётся отдельной строкой и печатается до пользовательского вывода задачи.

## Ожидаемое поведение

### Одиночный запуск

`exec MT01.EXE`

Должны появиться диагностическая строка ядра, затем строка `Task 01: ...`, после чего управление возвращается shell.

### Очередь

`execq 2 MT01.EXE`

Один и тот же EXE1 должен выполниться два раза, после чего очередь завершится и shell продолжит работу.

### EXECMT

`execmt MT01.EXE MT02.EXE MT03.EXE MT04.EXE`

Для каждой задачи сначала должна появиться отдельная диагностическая строка ядра `[MTxx] RUNNING ...`, а ниже — пользовательский вывод соответствующей `Task xx:`.

## Ограничение проверки

Полная сборка W64DevKit/Windows 7/QEMU в текущей среде не выполнялась. Выполнены статические проверки исходников и локальные синтаксические проверки, где это возможно.
