# ToyOS v67.11-B-FIX2 — исправление F10 quiet-маркера и явной индикации FAT16 LBA 512

## Основание

Базой является исходное дерево **v67.11-A → v67.11-B-FIX1**. Проверка исходников показывает, что перенос FAT16 действительно выполнен: `FAT_LBA/PART_LBA = 512` одновременно в ядре, построителе FAT16 и проверяющей утилите.

## Что обнаружено

### 1. SENSOR1..SENSOR4 продолжали печатать

В `user_shell.c` F10 действительно пытался добавить приватный маркер `q` к аргументам `RTD.EXE`, однако индексы были ошибочны: переменная `k` начиналась с `EXEC_ARG_SIZE`, а затем снова прибавлялась к `base=EXEC_ARG_SIZE`. В результате позиция поиска оказывалась за пределами блока и `q` фактически **не добавлялся**.

Поэтому `RTD.EXE` запускал SENSOR в обычном verbose-режиме через `SYS_RT_STATS`, и диагностические SENSOR1..4 печатали каждую измеренную итерацию.

Исправление: поиск конца аргументной строки начинается с `k=0` относительно второй половины блока.

Теперь:
- F10 → RTD получает `q`;
- RTD не включает `diag_verbose`;
- SENSOR1..4 работают в фоне молча;
- `rtstat`, `rtstat watch`, `rtstat dump` получают данные из ядра;
- прямой `exec RTD.EXE ...` по-прежнему может оставаться verbose для ручной диагностики.

### 2. Сообщение build.sh `128/128` было неправильно понято

Это **не размер FAT16**. Это размер отдельного слота kernel: LBA 1..128, то есть 128 секторов = 64 KiB. Загрузчик ToyOS исторически читает kernel именно из этого 128-секторного слота, поэтому менять это число только ради переноса FAT16 нельзя без изменения bootloader ABI/архитектуры загрузки.

FAT16 находится отдельно:

```text
LBA 0        BIOS boot sector
LBA 1..128   kernel slot (128 sectors)
LBA 129..511 reserved gap (383 sectors)
LBA 512      FAT16 boot sector
LBA 513...   FAT16 contents
```

Построитель `mkfat16.c` использует `PART_LBA=512`, ядро монтирует `FAT_LBA=512`, а `fat16check.c` проверяет FAT16 именно там. Это подтверждает, что v67.11-A действительно реализовала заявленный перенос, и v67.11-B-FIX1 продолжила именно эту базу.

## ABI

Изменения syscall ABI не вносятся. Номера 1..48 сохраняются. Новый RTDATA syscall 49 в этой версии **не добавляется**.

## Регрессии

Проверяются:
- FAT16 LBA 512 во всех трёх слоях;
- сохранение kernel slot 128 секторов;
- исправленный F10 quiet-маркер;
- отсутствие старой ошибочной арифметики;
- freestanding i386 syntax-only compilation kernel/user_shell/rtd/rt_sensor_diag с `-Werror`.

Полная сборка и загрузка QEMU в текущем окружении не выполнялись: отсутствуют требуемые W64DevKit/i686 и QEMU.
