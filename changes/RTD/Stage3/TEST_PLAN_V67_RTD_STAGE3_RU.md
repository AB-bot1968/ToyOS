# Test Plan — ToyOS v67 RTD Stage 3

## Контрольная версия

База: `ToyOS v67 RTD Stage 2 FIX2`.

## Шаг 0 — статическая проверка

Запустить:

```sh
sh ./check_rtd_stage3.sh
```

Ожидается:

```text
RTD stage 3 checks passed
```

## Шаг 1 — компиляция

Обязательно отдельно компилируются:

- `src/kernel.c`;
- `src/user_shell.c`;
- `src/rtd.c`;
- `src/rt_sensor.c`.

Все четыре должны пройти 32-bit freestanding compilation.

## Шаг 2 — одна RT-задача, регрессия FIX2

```text
exec RTD.EXE SENSOR.EXE 20 20 3
```

Проверить:

1. появляются `SENSOR: tick`;
2. задача не зависает после первого `SYS_RT_WAIT`;
3. ESC даёт `SENSOR: ESC -> stopped`;
4. появляется `toy0>`;
5. shell принимает следующую команду.

## Шаг 3 — две задачи

Сначала:

```text
exec RTD.EXE SENSOR.EXE 20 20 3
```

затем из вернувшегося shell:

```text
exec RTD.EXE SENSOR.EXE 40 40 7
```

Ожидается:

- продолжаются tick обеих независимых копий;
- более частая задача имеет период около 20 ms;
- вторая — около 40 ms;
- shell остаётся отзывчивым;
- нет `EXC 14`.

Так как обе программы печатают одинаковую строку, для точного различения
рекомендуется на runtime-тесте временно добавить в диагностический вывод
номер RT slot либо использовать разные периодические программы. Это не
требуется для проверки изоляции контекстов.

## Шаг 4 — независимое завершение

Нажать ESC.

Должна завершиться текущая RT-задача:

```text
SENSOR: ESC -> stopped
toy0>
```

Если вторая задача остаётся активной, её `tick` должны продолжаться.

Повторное ESC должно позволить завершить оставшуюся RT-задачу.

После завершения последней должна появиться:

```text
toy0>
```

## Шаг 5 — три задачи

```text
exec RTD.EXE SENSOR.EXE 20 20 1
exec RTD.EXE SENSOR.EXE 40 40 2
exec RTD.EXE SENSOR.EXE 100 100 3
```

Проверить независимость release/deadline state.

## Шаг 6 — четыре задачи

Запустить четыре экземпляра.
Пятая команда должна закончиться `EXE_ERR_BUSY`.

## Шаг 7 — задержка запуска

Проверить одновременно:

```text
exec RTD.EXE SENSOR.EXE 20 20 3 3000
exec RTD.EXE SENSOR.EXE 40 40 7
```

Задержка относится только к создаваемой задаче и не должна изменять период
уже работающей задачи.

## Шаг 8 — регрессия EXE1

Проверить обычные команды shell и обычный `exec` после завершения RT-задач.

## Шаг 9 — регрессия EXECMT

Проверить существующий `execmt`/`SYS_MT_START` после того, как все RT-задачи
завершены.

Пока RT-задачи активны, запуск EXECMT должен оставаться запрещённым, как в
предыдущих версиях.

## Ограничение среды разработки

Если `qemu-system-i386` отсутствует, runtime-тест не считается выполненным.
Статическая компиляция и focused checks не заменяют boot/runtime test.
