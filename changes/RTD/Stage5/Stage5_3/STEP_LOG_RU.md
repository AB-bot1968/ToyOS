# Stage 5.3 — журнал изменений по шагам

## Шаг 1. Зафиксирована политика no-backlog
После `SYS_RT_WAIT` система не создаёт очередь устаревших периодических jobs. Из номинальных release пропускаются все точки, которые уже остались в прошлом.

## Шаг 2. Добавлен wrap-safe расчёт следующего release
`rt_next_release_after()` получает текущий кандидат, `now`, период и возвращает первую release-точку, которая не находится строго в прошлом. Одновременно вычисляется число пропущенных release.

## Шаг 3. Сохранён точный boundary case
Если `now == next_release`, этот release не считается пропущенным. Следующая job может стать `READY` немедленно.

## Шаг 4. Разделены counters
`rt_missed_deadlines` — фактически созданные jobs с пропущенным deadline.

`rt_skipped_releases` — номинальные активации, которые не создавались как отдельные jobs из-за позднего завершения предыдущей job.

## Шаг 5. Добавлена идентификация job
`rt_job_sequence` увеличивается в `rt_begin_job()`. Это позволяет диагностике отличать старую job от следующей.

## Шаг 6. Добавлен диагностический ABI
`SYS_RT_JOB_INFO=44` возвращает 9 полей, не изменяя существующий `SYS_RT_DEADLINE_INFO=42`.

## Шаг 7. Добавлен обычный EXE1 `RTDSKIP.EXE`
Программа сознательно работает несколько PIT-tick и затем вызывает `SYS_RT_WAIT`, позволяя увидеть skip-ahead на реальной системе.

## Шаг 8. Добавлен host test
`tools/test_rt_period_release.c` проверяет один, несколько и wrap-around release.

## Шаг 9. Сохранена обратная совместимость
Старые тесты Stage 4.1–5.2 FIX2 обновлены только там, где они искали прежнюю текстовую реализацию. Поведение действующих RT механизмов не изменялось.
