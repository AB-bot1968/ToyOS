# ToyOS v67 RTD Stage 3 FIX4 — восстановление интерактивного shell при работающей RT-задаче

## Базовая версия

Исходная точка: `ToyOS v67 RTD Stage 3 FIX3`.

Исправление изолировано от завершения RT-задач (`ESC -> SENSOR: ESC -> stopped -> toy0>`) и от RT policy `period/deadline/priority`.

## 1. Наблюдаемая неисправность

После команды:

```text
exec RTD.EXE SENSOR.EXE 20 20 3
```

`SENSOR.EXE` начинал выдавать `SENSOR: tick`, но shell переставал быть практически доступен для ввода следующей команды.

## 2. Точная причина

После возврата RT-задачи в `SYS_CONSOLE_READ` ядро восстанавливало shell frame со специальным результатом `EAX=2`. `readline()` правильно игнорировал `2`, но немедленно повторно входил в `SYS_CONSOLE_READ`.

На новом входе syscall снова видел готовую RT-job и сразу переключал CPU обратно в RT. Получался цикл:

```text
RT -> shell(SYS_CONSOLE_READ, eax=2) -> SYS_CONSOLE_READ -> RT -> ...
```

Между двумя переключениями не существовало безопасного окна, в котором keyboard IRQ гарантированно мог передать следующий символ shell.

Дополнительная проблема была в `SYS_CONSOLE_POLL`: когда RT-задача исполнялась, она снимала из общей очереди **любые** клавиши, а не только `ESC`. Поэтому символы команды пользователя могли быть потреблены `SENSOR.EXE`.

## 3. Изменение №1 — `rt_shell_hold`

В `src/kernel.c` добавлен флаг:

```c
static volatile uint32_t rt_shell_hold;
```

Флаг означает: после возврата RT -> shell запрещено немедленно повторно выбирать RT на том же проходе `SYS_CONSOLE_READ`.

### Поведение

`rt_switch_to_shell()`:

1. сохраняет специальное значение `EAX=2`;
2. устанавливает `rt_shell_hold=1`;
3. восстанавливает shell CR3 и frame.

При следующем входе `SYS_CONSOLE_READ`:

1. сначала проверяется реальная клавиша;
2. если клавиши нет и установлен `rt_shell_hold`, флаг сбрасывается;
3. выполняется `sti; hlt; cli`;
4. после следующего аппаратного IRQ scheduler получает возможность либо принять клавишу, либо снова передать CPU RT.

Это устраняет непосредственный RT -> shell -> RT busy-loop.

## 4. Изменение №2 — исправление очереди клавиатуры RT

`SYS_CONSOLE_POLL` для текущей detached RT-задачи теперь возвращает только специальное событие `ESC`, полученное через `rt_stop_requested`.

Обычные клавиатурные байты RT больше не снимает из общей очереди `key_pop()`.

Следствие:

```text
ESC      -> RT stop request
A..Z,0..9,Enter,Backspace -> остаются для shell
```

Это необходимо для интерактивного shell при параллельно работающей RT-задаче.

## 5. Изменение №3 — безопасное сбрасывание состояния

`rt_shell_hold` сбрасывается:

- при старте первой RT-задачи;
- при получении реального символа shell;
- при завершении последней RT-задачи.

Это предотвращает перенос состояния между двумя независимыми сессиями RT.

## 6. Что намеренно не изменялось

Не изменялись:

- `SYS_RT_WAIT` и release/deadline accounting;
- преобразование `20/40/100 ms` в тики PIT 50 Hz;
- `ESC -> SENSOR: ESC -> stopped`;
- механизм возврата `toy0>` после последней RT-задачи;
- CR3/image/stack RT-задач;
- обычный EXE1 формат `SENSOR.EXE`;
- обычный EXE1 loader;
- существующий `EXECMT`;
- PIT 50 Hz;
- приоритетная политика Stage 2/Stage 3.

## 7. Ожидаемый результат

После:

```text
exec RTD.EXE SENSOR.EXE 20 20 3
```

shell остаётся интерактивным. Пока SENSOR выдаёт `tick`, пользователь может ввести следующую команду, например:

```text
exec RTD.EXE SENSOR.EXE 40 40 3
```

Обычные клавиши не должны исчезать в `SENSOR.EXE`; `ESC` остаётся командой остановки RT.
