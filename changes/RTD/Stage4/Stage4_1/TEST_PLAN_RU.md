# ToyOS v67 RTD — Stage 4.1: план тестирования

## Тест 1 — unit-test компаратора

Команда:

```sh
sh check_rtd_stage4_1.sh
```

Ожидаемый результат:

```text
RTD Stage 4.1 priority comparator checks passed
```

## Тест 2 — компиляция ядра

```sh
gcc -m32 -Os -ffreestanding -fno-pie -fno-stack-protector -nostdinc -nostdlib -c src/kernel.c -o /tmp/kernel.o
```

Ожидается успешная компиляция.

## Тест 3 — регрессия RTD Stage 3

Запустить все существующие RTD focused checks из базовой версии. Ни один из них не должен требовать изменения поведения priority selection, потому что Stage 4.1 его ещё не подключает.

## Тест 4 — runtime invariance

На реальной ToyOS не ожидается изменения поведения команды:

```text
exec RTD.EXE SENSOR.EXE 20 20 3
```

Должны сохраниться ранее подтверждённые `tick`, ESC-завершение и `toy0>`.

## Тест 5 — подготовка к Stage 4.2

Проверить, что `rt_pick_ready()` по-прежнему использует прежний критерий выбора. Этот факт фиксируется статической проверкой и обеспечивает изоляцию Stage 4.1.

## Ограничение

Stage 4.1 не предоставляет отдельного пользовательского способа наблюдать работу компаратора. Это намеренно: компаратор — подготовленная функция ядра для следующего этапа.
