# ToyOS v67 RTD Stage 6.1 FIX1 — защита контекста при 100 Hz IRQ0

## Причина

После перехода аппаратного PIT на 100 Hz вероятность IRQ0 внутри Ring-0 системного вызова стала вдвое выше, чем при старом 50 Hz. В прежней реализации `sched_irq_tick()` продолжал планирование detached RT даже если `f->cs=0x08`, то есть IRQ0 пришёл во время kernel-mode.

Это позволяло заменить текущий kernel interrupt frame на пользовательский RT frame прямо посреди `SYS_*` обработчика. Для `SENSOR1.EXE 10 10 3` такой случай особенно вероятен из-за одного RT tick на период и мог приводить к немедленному завершению/потере контекста задачи.

## Исправление

В начале ветки detached RT scheduler добавлена защита:

```c
if((f->cs&3u)==0u)return;
```

То есть IRQ0 в Ring-0 только обновляет временную базу. Контекстная смена RT выполняется только из действительно сохранённого Ring-3 interrupt frame.

`SYS_CONSOLE_READ` и `SYS_RT_WAIT` уже имеют собственные безопасные пути переключения и поэтому сохраняют прежнее поведение.

## Что не изменялось

- SYS_TIMER_GET = 50 Hz;
- SYS_RT_TIME_GET = 100 Hz;
- F10;
- ESC;
- SYS_RT_WAIT;
- release/deadline/priority;
- обычный EXE1 loader;
- EXECMT;
- VGA/text;
- shell.
