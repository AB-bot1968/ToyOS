# ToyOS v67 RTD Stage 3 FIX3 — тест-план

## 1. Базовый запуск

```text
exec RTD.EXE SENSOR.EXE 20 20 3
```

Ожидается `RTD: started ...`, затем `SENSOR: tick`.

## 2. Проверка shell

Не нажимая `ESC`, после появления `tick` ввести вторую команду:

```text
exec RTD.EXE SENSOR.EXE 40 40 3
```

Ожидается, что shell принимает команду, а первая RT-задача не должна быть принудительно завершена.

## 3. Проверка независимого завершения

После одновременного запуска двух RT-задач нажимать `ESC` по очереди. Каждое завершение должно быть корректным; после завершения последней задачи появляется `toy0>`.

## 4. Регрессия Stage 2

Проверить отдельно периоды 20, 40 и 100 ms и убедиться, что `SYS_RT_WAIT` продолжает блокировать job до следующего release.

## 5. Статические проверки

`check_rtd_stage3_fix3.sh` должен пройти полностью.

## Ограничение

Runtime QEMU должен выполняться на стенде, где доступен `qemu-system-i386`; локальная среда разработки без QEMU не считается runtime-подтверждением.
