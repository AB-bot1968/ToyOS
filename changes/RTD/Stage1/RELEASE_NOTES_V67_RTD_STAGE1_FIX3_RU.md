# ToyOS v67 RTD Stage 1 FIX3

## Исправление #PF после запуска/ESC

Исправлена опасная ситуация, при которой PIT IRQ0 мог выполнить `sched_irq_tick()` в момент, когда CPU находился внутри `INT 80h` syscall.

Хотя сохранённый interrupt frame имеет `CS=0x1b`, это ещё не означает, что CPU находится в безопасной точке вытеснения: ядро уже выполняет системный вызов. Сохранение/восстановление такого frame могло смешать контексты shell/RTD/SENSOR и привести к повреждённому пользовательскому состоянию и `EXC 14`.

Добавлен `syscall_dispatch_active`. Во время обработки `INT 80h`:

- PIT продолжает увеличивать `timer_ticks`;
- IRQ1 клавиатуры продолжает работать и может установить `rt_stop_requested` для ESC;
- переключение scheduler/RT-контекста через `sched_irq_tick()` запрещено;
- после выхода из syscall флаг снимается, и следующий PIT tick снова может выполнить обычное вытеснение.

Это минимальное изменение: частота PIT, ABI syscall, EXE1 loader, CR3/image/stack layout и существующий EXECMT scheduler не изменены.

## ESC

`SENSOR.EXE` остаётся обычной EXE1 программой. ESC обрабатывается через существующий `SYS_CONSOLE_POLL`; kernel дополнительно фиксирует запрос остановки в IRQ1, поэтому ESC не теряется, если SENSOR в данный момент не является foreground-контекстом.
