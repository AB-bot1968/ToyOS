## Исправление ошибки SYS_RT_START (-2)

Исправлена ошибка, из-за которой команда `exec RTD.EXE SENSOR.EXE 20 20 3` возвращала `FAIL code=4294967294`.

Причина была в проверке аргумента `SYS_RT_START`: ядро получало указатель на бинарную структуру `rt_start_request`, но проверяло этот указатель функцией `user_cstr()`, предназначенной для C-строк. Нулевые байты в полях `period_ms/deadline_ms/priority` ошибочно воспринимались как конец строки, после чего ядро возвращало `EXE_ERR_NAME = -2`.

Исправление не меняет существующий EXE1 ABI и не требует специального формата `SENSOR.EXE`: ядро сначала проверяет весь пользовательский диапазон структуры, затем проверяет только поле `req.name` как C-строку. Добавлен отдельный регрессионный тест `check_rtd_stage1_errorfix.sh`.

# ToyOS v67 — RTD stage 1

Первый этап подсистемы запуска RT-задач реализует команду:

```text
exec RTD.EXE SENSOR.EXE 50 50 3
```

где `SENSOR.EXE` остаётся обычным EXE1 Ring-3 приложением.

## Что добавлено

- `RTD.EXE` — обычный Ring-3 EXE1 launcher.
- `SENSOR.EXE` — обычная тестовая EXE1 программа, не требующая специального RT API.
- `SYS_RT_START = 38` — kernel syscall для регистрации одного detached RT task.
- Ring-3 shell распознаёт `exec RTD.EXE ...` и передаёт аргументы существующим `SYS_EXEC_ARGS` ABI без изменения общего механизма `exec`.
- RT task получает собственный CR3, физический image slot и стек на базе уже существующей EXECMT инфраструктуры.
- Shell продолжает работать как foreground context; RT task запускается независимо и вытесняется существующим IRQ0 scheduler.
- В `sched_task` сохраняются `period_ms`, `deadline_ms` и `priority`.

## Важное ограничение stage 1

В этой версии параметры `period_ms`, `deadline_ms` и `priority` валидируются и сохраняются, но ещё не влияют на алгоритм выбора/времени запуска. Scheduler stage 1 использует существующий 50 Hz IRQ0 механизм как безопасный механизм preemption.

Это сделано намеренно: сначала добавляется изолированный путь `RTD -> kernel -> ordinary EXE1` без изменения работающего EXECMT scheduler. На следующем этапе эти же поля будут подключены к release/deadline/priority policy.

## Совместимость

Не изменены форматы существующих EXE1, `exec`, `execmt`, `execq`, AUTOSTART.SH, FAT16, Ring-3 shell, NETDRV, VGADRV и существующие scheduler test tasks.


## FIX1/2

Исправлен критический дефект передачи запроса `RTD.EXE`: структура запроса
обнулялась после разбора числовых параметров, из-за чего `period/deadline/priority`
становились нулевыми и ядро возвращало `EXE_ERR_NAME` (`-2`, отображается как
`4294967294`). Теперь структура сначала инициализируется, затем заполняется
параметрами.

`SENSOR.EXE` получил штатное завершение по `ESC`. Клавиатурный IRQ фиксирует
запрос остановки RT-задачи, а сам SENSOR проверяет `ESC` через существующий
`SYS_CONSOLE_POLL` и завершает работу через `SYS_EXIT`. Если SENSOR в этот момент
не исполняется, ядро завершает detached RT-задачу на ближайшем IRQ0.
