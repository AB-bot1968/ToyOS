# Аудит syscall-test v18

## Покрытие

Команда `syscall-test` вызывает основные системные вызовы через пользовательский ABI `INT 80h`; в v23 добавлены интеграционные проверки `SYS_EXEC_QUEUE` (15) и `SYS_QUEUE_STOP` (16).

- 1 — `SYS_CONSOLE_WRITE`: контрольная строка, проверка возвращаемого количества байт.
- 2 — `SYS_CONSOLE_READ`: интерактивный ввод `OK` + Enter, повторный вызов до появления данных.
- 3 — `SYS_TIMER_GET`: два чтения, проверка `t1 >= t0`.
- 4 — `SYS_DISK_READ`: чтение LBA 129.
- 5 — `SYS_DISK_WRITE`: контрольный шаблон → запись → чтение → сравнение → восстановление исходного LBA 129 → повторная проверка.
- 6 — `SYS_FILE_OPEN`: создание/очистка временного файла и повторное открытие для чтения.
- 7 — `SYS_FILE_READ`: чтение 12 байт и побайтное сравнение.
- 8 — `SYS_FILE_WRITE`: запись 12 байт и проверка количества записанных байт.
- 9 — `SYS_FILE_CLOSE`: закрытие после записи и чтения.
- 10 — `SYS_FILE_DELETE`: удаление временного файла.
- 11 — `SYS_EXEC`: запуск штатного `HELLO.EXE`.
- 12 — `SYS_EXIT`: успешный выход выполняется `HELLO.EXE`; shell также отдельно проверяет отказ `SYS_EXIT` без активного EXE.

## Безопасность теста

LBA 129 находится между kernel slot LBA 1..128 и FAT16 LBA 130. Перед `SYS_DISK_WRITE` его содержимое сохраняется. При невозможности получить резервную копию запись не выполняется. После записи сектор восстанавливается и перечитывается.

Временный файл `SCT17.TMP` удаляется после файлового теста.

## Ограничения

Статический аудит и локальная 32-битная компиляция выполнены. Локальная ELF-аудит-сборка дала raw kernel 24441 байт при лимите 24576 байт. Runtime boot в QEMU в текущей среде не выполнялся, поскольку QEMU отсутствует.

## Исправление SYS_CONSOLE_READ (v18)

`SYS_CONSOLE_READ` теперь является блокирующим системным вызовом: после проверки пользовательского буфера ядро ждёт символ через `sti; hlt; cli`, пока IRQ1 не положит символ в клавиатурный буфер. За один вызов возвращается ровно один символ; `n=0` возвращает 0. Это устраняет прежнее активное вращение Ring-3 и делает поведение syscall соответствующим документации.

В shell добавлена отдельная проверка `0xffffffff`, чтобы ошибка проверки пользовательского буфера не могла использоваться как длина строки.
