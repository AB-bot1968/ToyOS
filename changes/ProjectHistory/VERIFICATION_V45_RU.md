# v45 — атомарная строка вывода EXECMT

## Исправление

В `src/execmt_task.c` начальная строка каждой `MTxx.EXE` больше не собирается несколькими вызовами `SYS_CONSOLE_WRITE`.

Теперь задача формирует полный текст `Task NN\n` в локальном буфере и передаёт его одним системным вызовом. Поэтому таймерное переключение задач не может разделить строку между несколькими задачами.

Диагностическая строка ядра `[MTxx] RUNNING ...` в `src/kernel.c` сохранена без изменений и по-прежнему печатается перед пользовательским выводом задачи.

Дополнительные диагностические строки Task 02/03 для проверки BLOCK/WAKE также сохранены.

## Ожидаемый вывод

Например:

```text
[MT01] RUNNING MT01.EXE CR3=... STACK=...
Task 01
[MT02] RUNNING MT02.EXE CR3=... STACK=...
Task 02
Task 02: BLOCKED, waiting for Task 03 wake
...
```

Строка `Task NN` является одним `SYS_CONSOLE_WRITE`.

## Проверка

Все 25 вариантов `src/execmt_task.c` (`EXECMT_ID=1..25`) успешно скомпилированы локально в 32-битном режиме с теми же freestanding-флагами, что используются для EXECMT в `build.sh`.

Полная сборка W64DevKit/Windows 7/QEMU в текущей Linux-среде не выполнялась, поскольку `gcc -dumpmachine` возвращает `x86_64-linux-gnu`, а штатный `build.sh` требует i686 W64DevKit.
