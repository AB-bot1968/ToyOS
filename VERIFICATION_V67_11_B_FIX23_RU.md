# Проверка FIX23: совместная работа RTD + EXECMT

## 1. Регрессия без RT
1. Загрузить систему.
2. `execmt MT01.EXE MT02.EXE MT03.EXE MT04.EXE`
3. Через 2-3 секунды выполнить `mtdata mt1` ... `mtdata mt4` — каждый слот должен содержать `MT0x:RUN;`.
4. Выполнить `mtstat`, затем `mtstat watch` на 5-10 секунд. DISPATCH и CPU_TICKS должны увеличиваться у всех четырех задач. ESC должен вернуть shell.
5. `mtstop all`.

Важно: MTSTAT WATCH перерисовывает экран раз в секунду. По частоте перерисовки нельзя судить о 20-ms переключении; смотреть нужно на прирост счетчиков.

## 2. Главная регрессия: сначала MT, затем RT
1. Запустить 4 MT как выше и убедиться, что MTDATA появилась.
2. Не останавливая MT, подготовить SENSOR1..SENSOR4 через RTD с прежними параметрами и нажать F10.
3. Не должно быть бесконечного `start FAIL code=4294967295`, ложного `active=8 free=0` или зависания shell.
4. `rtstat` должен показывать ровно 4 активных RT-слота.
5. `mtstat watch` 10 секунд: при исправной интеграции счетчики всех четырех MT должны продолжать расти, хотя RT имеет высший приоритет.
6. `mtdata mt1` ... `mtdata mt4` должны оставаться доступными.

## 3. Обратный порядок: сначала RT, затем MT
1. После `mtstop all` и `rtstat stop all` запустить SENSOR1..SENSOR4, затем `execmt MT01.EXE ... MT04.EXE`.
2. Проверить RTDATA SLOT1..SLOT4, RTSTAT, MTDATA MT1..MT4 и MTSTAT WATCH.
3. Остановить RT через `rtstat stop all`. MT должны продолжить работу без перезапуска.

## 4. Нагрузка 8 RT + 4 MT
1. Запустить SENSOR1..SENSOR8 и 4 MT в обоих порядках запуска.
2. Проверить отсутствие start FAIL/зацикливания.
3. Снять MTSTAT через 10, 30 и 60 секунд. DISPATCH/CPU_TICKS каждого MT должны либо расти, либо, если CPU действительно полностью занят RT, это должно быть видно вместе с RTSTAT; сама OS и shell не должны зависать.
4. Проверить RTSTAT WATCH/ESC и MTSTAT WATCH/ESC.

## 5. Проверка освобождения/повторного использования RT-слотов
`rtstat stop slot4`, затем подготовить один SENSOR и F10. Должен повторно использоваться свободный слот; active/free должны быть согласованы. Повторить для SLOT8.

## 6. Длительная проверка
После коротких тестов оставить 4 MT + 4 RT минимум на 30-60 минут. Снять RTSTAT, MTSTAT, RTDATA и MTDATA. Затем отдельно проверить 8 RT + 4 MT.

## Что прислать при ошибке
Точный порядок команд, вывод `rtstat`, один снимок `mtstat`, какие `mtdata` дают данные, параметры RTD (period/deadline/priority), и последнюю строку перед зависанием/FAIL.
