# v20 — исправление теста SYS_CONSOLE_READ

## Причина

`SYS_CONSOLE_READ` по текущему ABI является **символьным** системным вызовом: один успешный вызов записывает один байт в пользовательский буфер и возвращает `1`.

Интерактивный `echo TEST` это подтверждает: `readline()` вызывает `sys_console_read(&c,1)` в цикле, поэтому получает символы `T`, `E`, `S`, `T`, затем Enter.

Старый `syscall-test` ошибочно предполагал, что один вызов `sys_console_read(input,63)` вернёт всю строку. В результате после ввода `OK` первый вызов возвращал `n=1`, в `input[0]` был `O`, а проверка `n>=2 && input[1]=='K'` закономерно проваливалась.

## Исправление

Тест теперь делает три отдельных syscall-вызова:

1. читает `O` в `input[0]`;
2. читает `K` в `input[1]`;
3. читает Enter (`\n`) в `input[2]`.

После этого проверяется последовательность `OK\n`.

`SYS_CONSOLE_WRITE` отдельно остаётся проверенным вызовом `sys_console_write("console-write OK\n",17)`.

Дополнительно исправлен диагностический путь команды `syscall 2`: при возврате `0xffffffff` он больше не индексирует `x[r]` за пределами массива.

## Что не менялось

- ABI syscall'ов;
- номера SYS_CONSOLE_WRITE/SYS_CONSOLE_READ;
- обработчик SYS_CONSOLE_READ в kernel;
- Ring-3 модель;
- GDT/TSS/IDT/PIC/PIT;
- FAT16 и EXE1;
- адреса загрузки и linker script `liker.ld`;
- требования Windows 7 + W64DevKit x86.
