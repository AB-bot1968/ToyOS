# Проверка ToyOS v67.11-B FIX21

## Цель
Исправлена потеря ESC в `RTSTAT WATCH` при активных RTD. Причина: WATCH вызывает `SYS_RT_YIELD`; если IRQ клавиатуры с ESC приходил в момент исполнения SENSOR, старый обработчик относил ESC к RT-задаче как запрос остановки, а не к foreground WATCH.

## Обязательный тест
1. Собрать W64DevKit обычным `build.sh`; убедиться, что kernel <= 256 секторов.
2. Загрузить ОС и запустить SENSOR1..SENSOR8 через обычный механизм/F10.
3. Убедиться через `rtstat`, что слоты активны.
4. Выполнить `rtstat watch`. Дождаться минимум 5 обновлений (около 5 секунд).
5. Нажать ESC один раз. Ожидается немедленный выход из WATCH и возврат приглашения shell.
6. Сразу выполнить `rtstat`: все SENSOR1..SENSOR8, которые были активны до WATCH, должны оставаться активными. ESC не должен остановить случайный SENSOR.
7. Повторить вход/выход из WATCH 20 раз, нажимая ESC в разные моменты между обновлениями и непосредственно во время смены экрана.
8. Проверить `rtdata SLOT1` ... `rtdata SLOT8`: данные продолжают обновляться после выхода.

## Регрессии ESC
- В обычной shell ESC не должен создавать зависание.
- `RTSTAT STOP SLOTn` должен по-прежнему останавливать только указанный слот.
- Проверить прежний механизм ESC для контекстов, где он специально является stop-request, вне WATCH.
- Если используется EXECQ, отдельно проверить его прежний ESC-stop: при `queue_active` он имеет приоритет над WATCH-флагом по существующей логике.

## Совместный RT+MT
Запустить 8 RTD, затем EXECMT с несколькими MT-задачами. Войти в WATCH на 10–30 секунд, выйти ESC. После выхода проверить RTSTAT/RTDATA и MTLIST/MTDATA. Не должно быть остановленных RT из-за ESC и не должно быть повреждения MT-сессии.

## Что не изменялось
Алгоритм RT scheduler, выбор RT-задач, release/deadline, 20-ms MT quantum, RTDATA/MTDATA ABI, 6-часовые buckets, F10 RTD8, FAT16 LBA 512 и kernel area 256 не изменялись.

## Ограничение проверки
Host i386 freestanding compile/static checks можно выполнить вне W64DevKit, но окончательная проверка ESC требует реального QEMU/целевого окружения с IRQ клавиатуры.
