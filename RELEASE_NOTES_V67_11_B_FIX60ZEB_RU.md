# ToyOS v67.11-B FIX60ZEB

Исправлена регрессия FIX60ZEA, обнаруженная `TESTKEY.TST` строка 43.

## Причина
FIX60ZEA корректно закрывал пустую MT-сессию при естественном завершении последней MT-задачи, но одновременно вызывал `mt_data_clear_all()`. Это удаляло retained MTDATA завершившегося процесса раньше, чем `WAIT LAST` / `LAST_MTDATA` могли прочитать диагностический результат (`ARGVDIAG.EXE`).

## Исправление
При естественном EXIT последней MT-задачи теперь:
- `sched_active=0`;
- `mt_session_active=0`;
- `mt_session_count=0`;
- retained MTDATA не очищается.

MTDATA по-прежнему очищается перед началом следующей MT-сессии (`process_spawn`/`execmt_prepare`) и при явном `mtstop ALL`.

Таким образом одновременно выполняются оба контракта: новая EXECMT-сессия не блокируется stale-флагом, а результат только что завершившегося процесса остаётся доступен для диагностики.
