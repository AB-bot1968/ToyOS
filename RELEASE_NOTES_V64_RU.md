# Toy OS v64 — `cp` + полные регрессии + граничные тесты

## Основа релиза
v64 начинается строго от проверенной `ToyOS v63.1`. Изменения v63.1 не переписаны заново:
сохраняются FAT16-каталоги, kernel-side CWD, standalone `path.c`, `ls` с относительными путями,
защита `rmdir` от удаления CWD/предков и исправленный относительный `rmdir B` из `/A`.

## Новая команда `cp`
Добавлен syscall `31` (`SYS_FILE_COPY`) и shell-команда:

```text
cp SOURCE DEST
```

Поддерживаются относительные и абсолютные пути. Если `DEST` является каталогом, копия создаётся
как `DEST/BASENAME(SOURCE)`. Каталоги как SOURCE не копируются. Если SOURCE и конечный DEST
совпадают после нормализации, операция отклоняется.

### Безопасность перезаписи
v64 не делает обычный `TRUNC` целевого файла перед копированием. Сначала создаётся и полностью
заполняется новая цепочка FAT-кластеров. Только после успешной записи directory entry переключается
на новую цепочку; старая цепочка освобождается после этого. Поэтому ошибка чтения/записи/нехватка
места не должна уничтожать старое содержимое существующего DEST.

## Постраничный `help`
Справка больше не является одной длинной строкой. Теперь:

```text
help
help 1
help 2
help 3
help 4
```

Показывают четыре страницы. Первая страница содержит файловые команды, включая новый `cp`.
После страницы выводится подсказка перейти дальше. Неверные номера страниц отклоняются с usage.

Это правило теперь является частью архитектуры shell: при добавлении новой команды она должна быть
явно помещена на одну из страниц `help_page()` и покрыта статической регрессией.

## Новые проверки
- `check74.sh` — wiring syscall 31, shell `cp`, постраничный help.
- `check75.sh` — защита copy: каталоги, source==destination, нормализация, rollback-цепочка.
- `check76.sh` — наличие старых и новых команд на страницах help и границы 1..4.
- `check77.sh` — граничный разбор `cp SOURCE DEST` и отказ от лишних аргументов.

Полный список прежних `check*.sh` также остаётся в `build.sh`.
