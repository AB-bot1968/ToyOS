# ToyOS v67.3 — регистронезависимые параметры драйверов

## Цель изменения

После v67.1 имя команды/EXE в shell стало нечувствительным к регистру, а в v67.2 аналогичная нормализация была добавлена для имени RT-цели `RTD.EXE`. При этом четыре драйверных интерфейса всё ещё сравнивали некоторые текстовые параметры буквально в верхнем регистре.

В результате варианты `SEND`, `RECV`, `MASTER`, `SLAVE1`, `SLAVE2`, `COM1` и имена VGA-ресурсов могли зависеть от регистра.

v67.3 устраняет эту рассогласованность без изменения syscall ABI и без изменения формата EXE1.

## Изменения по файлам

### `src/comdrv.c`

Добавлена локальная функция `upper_copy()` для ASCII upper-case.

Нормализуются:

- номер COM-порта (`com1` -> `COM1`);
- направление (`send` -> `SEND`, `recv` -> `RECV`).

После нормализации существующий `parse_port()` и `eq4()` продолжают использоваться без изменения их интерфейса.

Имя файла не преобразуется на уровне COMDRV. Оно передаётся в существующий FAT16 syscall; файловая подсистема ToyOS уже выполняет регистронезависимую нормализацию пути.

### `src/loader.c`

Нормализуется параметр направления.

Теперь:

`LOADER.EXE 1 recv file.exe`

и

`LOADER.EXE 1 RECV FILE.EXE`

имеют одинаковую семантику.

В очередь `COMDRV.EXE` передаётся уже каноническое `RECV`, поэтому поведение не зависит от регистра на первом этапе.

Порт и имя конечного EXE не преобразуются искусственно: порт обрабатывается COMDRV, а имя EXE проходит существующий регистронезависимый поиск FAT16.

### `src/netdrv.c`

Добавлена локальная `upper_copy()`.

Нормализуются текстовые параметры:

- `TELEMETRY`;
- `MASTER`;
- `SLAVE1`;
- `SLAVE2`;
- `SEND`;
- `RECV`.

IP-адрес и имя файла не изменяются. Числовые параметры также не изменяются.

Таким образом поддерживаются, например:

```text
exec netdrv.exe 10.0.2.2 send test.txt
exec NETDRV.EXE TELEMETRY master 5000
exec netdrv.exe telemetry slave1 10.0.2.10
```

### `src/vgadrv.c`

Имя VGA-файла перед `SYS_FILE_OPEN` явно нормализуется в ASCII upper-case.

Это не меняет содержимое файла и не меняет ABI. Нормализация добавлена для единообразия поведения драйверов; FAT16 также остаётся регистронезависимым уровнем поиска.

## Что намеренно НЕ изменяется

- syscall ABI;
- формат EXE1;
- размеры ABI-полей по 16 байт;
- числовые параметры;
- IP-адреса;
- содержимое передаваемых файлов;
- историю команд shell;
- регистр исходной строки, отображаемой в консоли;
- FAT16 и алгоритм `path_normalize()`.

## Ожидаемое поведение

Следующие варианты должны иметь одинаковую семантику:

```text
exec COMDRV.EXE 1 SEND TEST.TXT
exec comdrv.exe com1 send test.txt
exec CoMdRv.ExE CoM1 SeNd TeSt.TxT
```

```text
exec NETDRV.EXE 10.0.2.2 SEND TEST.TXT
exec netdrv.exe 10.0.2.2 send test.txt
```

```text
exec NETDRV.EXE TELEMETRY MASTER 5000
exec netdrv.exe telemetry master 5000
exec netdrv.exe TeLeMeTrY sLaVe1 10.0.2.10
```

```text
exec LOADER.EXE 1 RECV FILE.EXE
exec loader.exe 1 recv file.exe
```

```text
exec VGADRV.EXE SPLASH.RAW
exec vgadrv.exe splash.raw
```

## Регрессии

Изменение ограничено точками разбора параметров. Существующие проверки ошибок, коды syscall, порядок запуска очередей и файловые операции сохранены.
