# ToyOS v67.11-B-FIX1 — исправление фонового RT-вывода

## Причина

После F10 SENSOR-задачи продолжали писать `SENSOR: started...` и `SENSOR: tick` непосредственно в интерактивную консоль. Эти записи конкурировали с prompt `toy0>` и визуально/логически повреждали интерактивный ввод.

## Исправление

- SENSOR1..SENSOR4 по умолчанию полностью молчат.
- Их timing-информация остаётся в RTSTAT.
- Будущий прикладной вывод должен передаваться через RTDATA, а не через `SYS_CONSOLE_WRITE`.
- F10 добавляет внутренний `q` к спецификации RTD, поэтому launcher не печатает `RTD: started...` для фонового запуска.
- Обычный интерактивный `exec RTD.EXE ...` не изменён и остаётся диагностически информативным.
- ABI syscall 1..48 не изменён.

## Поведение

После F10 ожидается обычный prompt без асинхронных строк SENSOR:

```text
toy0>
```

Затем пользователь может сразу выполнить:

```text
rtstat
rtstat watch
rtstat stop sensor1
rtstat stop
```

## Проверка

`check139.sh` выполняет строгую freestanding i386 syntax-проверку изменённых исходников и проверяет отсутствие старого фонового SENSOR-вывода.
