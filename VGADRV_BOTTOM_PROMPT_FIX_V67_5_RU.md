# ToyOS v67.5 — исправление положения `VGADRV: OK` и `toy0>`

## 1. Симптом

После загрузки `SPLASH.RAW` корректно отображается. При нажатии клавиши kernel возвращает VGA в текстовый режим, однако строка:

`VGADRV: OK`

и следующий prompt:

`toy0>`

появлялись в левом верхнем углу вместо левого нижнего.

## 2. Причина

В версии v67.4 обработчик `SYS_VIDEO_TEXT` выполнял `console_clear()` и явно устанавливал курсор в `(0,0)`. Это было сделано намеренно для устранения мусора от графического режима.

После этого `VGADRV.EXE` использовал обычный `SYS_CONSOLE_WRITE` для строки `VGADRV: OK`. Поэтому kernel начинал вывод с позиции `(0,0)`, а shell продолжал работу оттуда же.

Сам `SYS_CONSOLE_AT` для исправления этого поведения использовать нельзя: этот syscall по своему контракту пишет в фиксированную позицию и **не изменяет текущий cursor shell**, поскольку он используется, в частности, для телеметрии.

## 3. Исправление

Изменён только успешный путь завершения `VGADRV.EXE`:

1. После `SYS_VIDEO_TEXT` kernel уже гарантированно установил чистый текстовый режим и курсор `(0,0)`.
2. `VGADRV.EXE` выводит 24 символа перевода строки отдельными логическими записями.
3. Курсор перемещается с строки `0` на строку `24`, то есть в левый нижний ряд стандартного режима 80x25.
4. Вместо `"VGADRV: OK\\n"` выводится `"VGADRV: OK "` без завершающего LF.
5. Shell сразу выводит `"toy0> "`, поэтому итоговая строка начинается в левом нижнем углу и имеет вид:

`VGADRV: OK toy0> `

## 4. Почему не добавлен новый syscall

Новый syscall для установки cursor не нужен и нежелателен: существующий ABI сохраняется полностью. Изменение использует уже существующую семантику `SYS_CONSOLE_WRITE` и текущего cursor kernel.

`SYS_CONSOLE_AT` также не изменялся, поэтому телеметрия и другие фиксированные экранные выводы не получают побочного эффекта.

## 5. Что не изменилось

- syscall ABI;
- `SYS_VIDEO_TEXT`;
- `SYS_CONSOLE_AT`;
- FAT16;
- `SPLASH.RAW`;
- shell history;
- регистронезависимость команд;
- нормализация параметров драйверов;
- аргументный ABI EXE1;
- обработка ошибок VGADRV.

## 6. Проверка

`check131.sh` проверяет наличие нижнерядного позиционирования и отсутствие старой строки `VGADRV: OK\\n`.

Изменённые `src/vgadrv.c` и `src/kernel.c` отдельно скомпилированы с теми же freestanding-флагами ToyOS в 32-битном режиме GCC — ошибок компиляции нет.

Полная `build.sh` в текущей среде не запускалась, поскольку проект требует предусмотренный им i686/W64DevKit toolchain.
