# ToyOS v67.4 — исправление автозапуска SPLASH.RAW и артефактов первого `ls`

## Симптомы

Наблюдались два связанных с переходом VGA → text-mode симптома:

1. При автоматическом запуске `VGADRV.EXE` заставка исчезала и появлялось
   сообщение `VGADRV: image open failed`.
2. После возврата в shell начало первого вывода `ls` визуально содержало
   мусор/остатки предыдущего экранного состояния.

## Причина 1 — скрытая зависимость пути ресурса

`AUTOSTART.SH` передавал `SPLASH.RAW` как относительное имя. Сам VGADRV уже
нормализовал регистр имени, но открывал ресурс всё ещё относительно текущего
каталога shell. Для автоматического графического ресурса это ненужная
зависимость от cwd.

### Исправление

`resources/AUTOSTART.SH` теперь запускает:

`exec VGADRV.EXE /SPLASH.RAW`

Дополнительно `VGADRV.EXE` перед `SYS_FILE_OPEN` формирует абсолютный путь
`/SPLASH.RAW`. Для совместимости интерактивных запусков сохранён резервный
относительный `file_norm`.

Регистр имени при этом по-прежнему нормализуется в ASCII upper-case.

## Причина 2 — аварийный выход VGADRV из graphics mode

Ранее `fail_and_exit()` выводил текст ошибки, снимал user mapping VRAM и
сразу выполнял `SYS_EXIT`. При ошибке открытия файла аппаратный VGA уже мог
оставаться в Mode 13h. `SYS_EXIT` возвращал shell-контекст, но сам по себе не
являлся гарантированным восстановлением text-mode.

### Исправление

`fail_and_exit()` теперь выполняет в строгом порядке:

1. `SYS_VIDEO_TEXT`;
2. `SYS_VIDEO_UNMAP`;
3. вывод диагностического сообщения;
4. `SYS_EXIT(1)`.

Таким образом любой аварийный выход после `SYS_VIDEO_MAP` оставляет shell в
нормальном VGA text mode.

## Причина 3 — положение курсора после восстановления VGA

`SYS_VIDEO_TEXT` очищал B8000, но затем принудительно устанавливал курсор в
`H-2`. Это было сделано для старого оформления `VGADRV: OK`, но после ошибки
или первого интерактивного `ls` могло оставлять визуально confusing состояние
начала нового shell-сеанса.

### Исправление

После `vga_restore_saved_font()` выполняется полный `console_clear()`, после
чего курсор устанавливается в `(0,0)`.

Это не меняет API консоли, шрифт, FAT16 или shell ABI.

## Что намеренно не менялось

- формат FAT16;
- расположение `SPLASH.RAW` в образе;
- размер splash — 64000 байт;
- syscall ABI;
- EXE1 ABI;
- история команд;
- регистронезависимость команд и параметров драйверов;
- логика `ls` и порядок FAT directory entries.

## Ожидаемое поведение

При загрузке:

1. `AUTOSTART.SH` запускает `/SPLASH.RAW`;
2. `VGADRV.EXE` открывает ресурс независимо от cwd;
3. заставка остаётся на экране до клавиши пользователя;
4. после клавиши выполняется полноценный возврат в text mode;
5. shell начинается с чистого экрана в позиции `(0,0)`;
6. `ls` выводит только содержимое каталога, без остатков графического экрана.
